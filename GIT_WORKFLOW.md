# Git Repository Management Guide

## ✅ What to COMMIT (Code & Configuration)

### Always commit these changes:
- **Source code changes** (`src/*.py`)
- **Configuration updates** (`config/*.yml`)
- **Documentation** (`*.md` files)
- **Scripts** (`*.sh`, `*.bat`, `*.ps1`)
- **Tests** (`tests/*.py`)
- **GitHub Actions** (`.github/workflows/*.yml`)
- **Dependencies** (`requirements.txt`)

### Example workflow:
```bash
# If you improved the code or config
git add src/filters.py config/nfirs_codes.yml
git commit -m "Add new NFIRS codes for 2024 battery types"
git push
```

---

## ❌ What NOT to COMMIT (Data & Generated Files)

### NEVER commit these (already in .gitignore):
- **❌ NFIRS data files** (`data/*.csv`, `data/*.zip`, `data/*.txt`)
  - Reason: Large files (100MB+), copyrighted data, changes frequently

- **❌ Generated reports** (`reports/*.html`, `reports/*.csv`, `reports/*.json`)
  - Reason: Generated output, can be recreated anytime

- **❌ Log files** (`logs/*.log`)
  - Reason: Temporary, machine-specific

- **❌ Python cache** (`__pycache__/`, `*.pyc`)
  - Reason: Auto-generated by Python

- **❌ Virtual environments** (`venv/`, `env/`)
  - Reason: Environment-specific, large

---

## 🔍 Check What Will Be Committed

Before committing, always check:

```bash
# See what changed
git status

# See actual changes in files
git diff

# See which files are staged
git diff --cached
```

## 🎯 Recommended Workflow

### For Your First Analysis Run:

1. **Check status:**
   ```bash
   git status
   ```

2. **Review any changes:**
   ```bash
   git diff
   ```

3. **Decision tree:**
   - **No changes?** ✅ Perfect! Data and reports are ignored.
   - **Only code improvements?** ✅ Commit them!
   - **Accidentally added data files?** ⚠️ Don't commit! See below.

### If You Accidentally Staged Data Files:

```bash
# Unstage large files
git reset data/*.csv
git reset reports/

# Verify .gitignore is working
git check-ignore data/basicincident.csv  # Should show the file
```

## 📊 Best Practices for This Project

### 1. **Keep Data Local**
- ✅ Store NFIRS data in `data/` directory
- ✅ It's automatically ignored by git
- ✅ Each user maintains their own data

### 2. **Share Code, Not Data**
- ✅ Commit improvements to filtering logic
- ✅ Commit new NFIRS codes you discover
- ✅ Commit bug fixes and enhancements
- ❌ Don't commit CSV files or reports

### 3. **Use Branches for Experiments**
- Create feature branches for major changes:
  ```bash
  git checkout -b feature/improve-battery-detection
  # Make changes
  git commit -m "Add advanced battery fire detection"
  git push origin feature/improve-battery-detection
  ```

### 4. **Document Your Changes**
- Update relevant `.md` files when adding features
- Add comments to code explaining complex logic
- Update `config/nfirs_codes.yml` comments for new codes

### 5. **Sync Regularly**
```bash
# Pull latest changes before starting work
git pull origin claude/nfirs-workflow-development-011CUuvJsdowyQMjTrxWdeqJ

# Push your improvements when done
git push origin claude/nfirs-workflow-development-011CUuvJsdowyQMjTrxWdeqJ
```

## 🔧 Useful Git Commands

### Check what's ignored:
```bash
# Check if a file is ignored
git check-ignore data/basicincident.csv

# List all ignored files
git status --ignored
```

### Clean up unwanted files:
```bash
# Remove untracked files (careful!)
git clean -n  # Dry run - see what would be removed
git clean -f  # Actually remove

# Remove ignored files
git clean -X -f
```

### Undo mistakes:
```bash
# Unstage a file
git reset HEAD data/somefile.csv

# Discard local changes to a file
git checkout -- src/filters.py

# Undo last commit (keep changes)
git reset --soft HEAD~1
```
